# 刷题 · 本地题库

本地优先的刷题题库系统。题库和答题记录保存在浏览器 IndexedDB 中，不需要账号和服务器，适配电脑与手机。

## 技术栈

- React 19 + TypeScript + Vite
- Tailwind CSS v4
- React Router
- Zustand
- Dexie（IndexedDB）
- read-excel-file / write-excel-file / PapaParse / Mammoth（导入导出）
- Vitest（解析器单元测试）
- Playwright Core（UI 冒烟测试）

## 启动方式

### 环境要求

- Node.js（建议 20 及以上）与 npm
- 现代浏览器（Chrome / Edge / Firefox / Safari）；数据保存在浏览器 IndexedDB 中

### 开发模式（日常使用）

在项目根目录执行：

```bash
npm install     # 首次克隆或依赖缺失时执行一次
npm run dev     # 启动 Vite 开发服务器
```

然后在浏览器打开 <http://localhost:5173>。开发服务器支持热更新，修改代码后页面会自动刷新，按 `Ctrl+C` 停止。

如果依赖已经安装过（存在 `node_modules` 目录），可以跳过 `npm install` 直接运行 `npm run dev`。

### 生产构建与本地预览

```bash
npm run build    # tsc -b 类型检查 + vite build，产物输出到 dist/
npm run preview  # 以 HTTP 服务预览 dist/ 中的构建结果
```

> 不能直接双击 `dist/index.html` 打开——这是单页应用，路由和静态资源需要 HTTP 服务，本地查看请用 `npm run preview`，正式使用则把 `dist/` 部署到任意静态托管平台。

### 手机访问

手机和电脑连接同一个 Wi-Fi，用电脑的局域网 IP 访问开发服务器，例如 `http://192.168.1.10:5173`。

开发服务器默认只监听本机，手机访问不到时用 `--host` 暴露到局域网：

```bash
npm run dev -- --host
```

正式使用和 PWA 安装建议部署到静态托管平台。

## 导入题库

导入页支持 `.xlsx` / `.xlsm` / `.csv` / `.txt` / `.md` / `.docx`，会先预览校验，再确认写入。导入前可以：

- 选择已有题库，或直接新建题库
- 自动跳过文件内和目标题库中的重复题（题型 + 题干）
- 查看错误行、警告和题目的答案摘要
- 把解析结果导出为 CSV / Excel
- 把校验结果导出为 CSV，修改后重新上传
- 下载 Excel / CSV / TXT 模板

> `.xls` 和旧版 `.doc` 不受支持。请在 Excel / Word 中另存为 `.xlsx` / `.docx`。图片题和 Word 中的图片不会被导入。

### 表格格式

第一行是表头，一行一题。列名可以使用以下别名：

| 列名 | 必填 | 说明 |
| --- | --- | --- |
| 题型 | 建议 | 单选 / 多选 / 判断 / 填空 / 简答；留空时根据选项和答案推断 |
| 题干 | 是 | 填空题用 `____` 表示空 |
| 选项A–H | 选择题 | 至少两个选项 |
| 答案 | 是 | 见下方答案格式 |
| 解析 | 否 | 作答后展示 |
| 章节 | 否 | 用于筛选和统计 |
| 难度 | 否 | 易 / 中 / 难，默认中 |
| 标签 | 否 | 用逗号、顿号、分号或竖线分隔 |
| 关键词 | 简答 | 用逗号、顿号、分号或竖线分隔；留空表示自评 |

答案格式：

| 题型 | 写法 |
| --- | --- |
| 单选 | `A` |
| 多选 | `ABC` |
| 判断 | `对` / `错`、`正确` / `错误`、`√` / `×`、`true` / `false` 均可 |
| 填空 | 多个空用 `；` 分隔，同一个空的多个写法用竖线分隔，例如 `北京&#124;首都；中国` |
| 简答 | 参考答案全文 |

### TXT / Word 格式

TXT 和 Word 正文按题号分隔题目，支持 `1.`、`1、`、`（1）`、`第 1 题` 等写法，也支持 `【单选】`、`[多选]`、`（判断）` 等题型标记。

```text
1. 【单选】中国的首都是哪座城市？
A. 北京
B. 上海
C. 广州
D. 深圳
答案：A
解析：北京是中华人民共和国的首都。
章节：地理
难度：易
标签：常识

2. 【判断】标准大气压下，水的沸点是 100°C。
答案：对

3. 【填空】中国的首都是____，人口最多的城市是____。
答案：北京|首都；上海

4. 【简答】简述光合作用对地球生命的意义。
答案：光合作用把光能转化为化学能，制造有机物，并释放氧气。
关键词：光能|有机物|氧气
```

字段名支持 `答案 / 正确答案 / 参考答案 / 标准答案`、`解析 / 答案解析`、`章节 / 分类 / 知识点`、`难度`、`标签`、`关键词`。

Word（`.docx`）会优先读取文档中的表格；表格表头与上面的表格格式一致。如果没有可识别的表格，会按 TXT 规则解析正文。解析不理想时，可以在预览页把识别结果导出为 Excel / CSV，修正后再导入。

## 题目管理

在题库详情页可以：

- 按关键词、题型、章节、难度筛选
- 分页浏览题目
- 手动添加五种题型的题目
- 编辑题干、选项、答案、解析、章节、难度和标签
- 删除题目（同时清除这道题的练习记录）

## 练习与判分

在题库详情页点击「开始练习」，可以选择：

- **顺序练习**：按题库顺序逐题作答
- **随机练习**：打乱顺序自测
- **错题重练**：集中练习答错过的题（答错记录会自动积累）
- **收藏练习**：只练习标记过星标的题目

开始前可以按题型、难度、章节筛选，并选择题量（5 / 10 / 20 / 50 / 100 或全部可用题目）。练习过程中：

- 提交后立即判分，并展示正确答案和解析
- 单选题按唯一选项判分，多选题按选项集合判分（顺序无关），判断题按对 / 错判分
- 填空题按空逐个判分，同一个空支持多个可接受写法；比较时忽略大小写、全半角、空格和常见标点
- 简答题配置了关键词时按关键词覆盖情况判分；没有关键词时展示参考答案，由自己选择「算答对」或「需要复习」
- 答题记录自动保存，退出后可以从首页或题库详情页继续，重新打开正在作答的题也会保留判分结果
- 每道题连续答对 3 次后自动标记为「已掌握」，答错会重置连续答对次数
- 练习页和题目列表都可以点击星标收藏题目

本次练习结束后会展示正确率、用时和错题清单。

## 错题、收藏与掌握

顶部导航的「错题」页面统一管理三类题目：

- **错题**：作答错误的题会自动收录，并在答错次数中记录；连续答对 3 次或手动标记「已掌握」后自动移出，也可以手动移出。
- **收藏**：在题目列表或练习页点击星标即可收藏；收藏页可以集中查看和重练。
- **已掌握**：连续答对 3 次自动标记，也可以手动标记；支持取消掌握，取消后回到学习状态，曾经的错题会重新出现在错题本。

页面支持按题库、题型筛选，也可以搜索题干、章节或标签。选中单个题库后，可以用当前筛选结果直接开始针对性练习，不会受题库顺序或题量设置影响。

## 备份与恢复

设置页提供：

- 导出 JSON 备份（包含题库、题目、题目状态、练习记录和设置），点击时读取当时的数据
- 自动备份：页面打开期间按设置的间隔（5 / 10 / 15 / 30 / 60 分钟）自动下载一份带时间戳的 JSON
  - 默认开启，间隔 10 分钟；可在设置页随时关闭或调整
  - 标签页隐藏时暂停，回到页面后如果已超过间隔会立即补一份
  - 自动备份只在页面打开时运行，关闭页面后停止
  - 浏览器首次连续下载多个文件时可能询问是否允许，需要选择允许，否则后续自动备份会被拦截
- 练习页顶部也有一个导出按钮，做题过程中可以随时手动导出点击前的全部数据
- 导入备份：合并导入（相同 ID 以备份为准）或覆盖恢复（先清空当前数据）
- 清空本机全部数据

数据只保存在当前浏览器中，清理浏览器数据、使用无痕模式或更换设备都会导致数据丢失，建议定期导出备份。

## 部署到 GitHub Pages

仓库 `Yukino-yae/quiz` 对应的访问地址是 <https://yukino-yae.github.io/quiz/>。项目已包含 `.github/workflows/deploy.yml`，推送到 `main` 后会自动构建并发布。

首次部署：

1. 打开 GitHub 仓库的 **Settings → Pages**；
2. 在 **Build and deployment → Source** 中选择 **GitHub Actions**；
3. 推送到 `main`，或在 **Actions → Deploy to GitHub Pages → Run workflow** 手动触发；
4. 等待 `build` 和 `deploy` 两个 job 完成，打开上面的地址。

工作流会：

- 执行 `npm ci` 和 `npm run build:pages`；
- `build:pages` 使用 Vite 的 `pages` 模式，把资源路径前缀设为 `/quiz/`；
- 把 `dist/index.html` 复制为 `dist/404.html`，让 `/quiz/practice/...` 这类深链接在 GitHub Pages 上仍能由前端路由接管；
- 上传 `dist/` 到 GitHub Pages。

本地验证 Pages 构建：

```bash
npm run build:pages
npm run preview -- --mode pages
# 打开 http://localhost:4173/quiz/
```

注意事项：

- 仓库名配置在 `vite.config.ts` 的 `PAGES_REPO_NAME`。如果仓库改名，或部署到用户主页仓库（`<用户名>.github.io`），需要相应修改；用户主页应使用 `/`。
- 浏览器数据按源（协议 + 域名 + 端口）隔离。从 `localhost` 切换到 `https://yukino-yae.github.io` 后看不到旧数据，请先在设置页导出 JSON 备份，再在新地址导入。
- 首次连续自动下载多个备份文件时，浏览器可能要求允许下载多个文件；在 Pages 域名下同样需要允许。

